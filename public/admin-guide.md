## Вхід Ірини

- На власному підключеному домені: `https://ваш-домен/admin/insights`.
- Email: piletskaya.i@empatixtech.com. Обліковий запис уже існував; його права змінено на Editor. Інші адміністратори збережені.
- Надіслано лист для встановлення пароля. Відкрийте його після публікації оновлення; якщо посилання прострочене, натисніть Forgot password? на /admin/login.
- Editor має доступ лише до Insights та особистої зміни пароля, не до інших сторінок або Users.

## Статті
1. Insights → New article.
2. Заповніть заголовок, URL, категорію, дату, обкладинку та текст. URL генерується із заголовка; його можна змінити. Для нелатинського заголовка вкажіть латинський URL.
3. Library дозволяє завантажити або вибрати обкладинку. Великі фотографії стискаються автоматично. Додайте опис зображення.
4. У тексті доступні H2/H3, жирний, курсив, списки, посилання та зображення через бібліотеку.
5. Save draft зберігає чернетку без показу відвідувачам. Preview відкриває наявний шаблон статті.
6. Publish показує статтю в Insights, категоріях і пагінації та за /insights/URL.
7. Unpublish & save draft приховує статтю. Видалення потребує підтвердження.
8. SEO title і Meta description необов’язкові: за відсутності використовуються заголовок та excerpt.

## Користувачі — тільки Administrator
- Users → email → Editor або Administrator → Send invitation. Користувач сам встановлює пароль із листа. Готові паролі не надсилаються.
- Ролі в рядку користувача можна надавати й відкликати. Для переходу Administrator → Editor спочатку увімкніть editor, потім відкличте admin.
- Значок конверта повторно надсилає посилання встановлення/скидання пароля. Для існуючих облікових записів це лист відновлення пароля.
- Block/Enable закриває/відновлює доступ. Delete видаляє обліковий запис після підтвердження.
- Не можна блокувати або видаляти власний обліковий запис; останнього активного адміністратора також захищено. Super Admin залишається наявною підвищеною роллю й керується лише Super Admin.

## Паролі
- Забули пароль: /admin/login → Forgot password? → email → лист → новий пароль → вхід.
- Зміна власного: Account → поточний пароль → новий пароль та підтвердження → Change password.
- Мінімум 12 символів; сервіс входу може відхилити ненадійний пароль.
- Sign out очищає сесію та закриває доступ до адмінки.

## Що перевірено й що ще потрібно для production
- Email/password увімкнений у Lovable Cloud (перевірено налаштування сервісу).
- Site URL: https://empathic-site-studio.lovable.app. Дозволені адреси містять опублікований домен та його сторінки /admin/reset-password.
- Запит листа Ірині прийнятий сервісом (200). Доставку до її поштової скриньки та відкриття листа самим користувачем не підтверджено.
- Налаштування власного SMTP/домену відправника не підтверджені. Для стандартних листів входу працює наявна доставка Lovable Cloud; власний SMTP не потрібен для реалізованого сценарію. Брендований відправник налаштовується через More → Emails із перевіркою домену.
- Перед використанням нового інтерфейсу натисніть Publish → Update. Автентифікація та ролі вже збережені; сама нова сторінка з’явиться на опублікованому сайті після оновлення.
- Після підключення власного домену перевірте More → Users → Auth settings → Advanced: Site URL та Redirect URLs повинні включати ваш домен і шлях /admin/reset-password (або / ** без пробілу). Lovable синхронізує підключені домени, але фактичну конфігурацію ще не підключеного домену неможливо перевірити наперед.
- Запрошення з опублікованої адмінки використовують її HTTPS-домен; запити з робочого превью використовують поточний опублікований сайт.
- Наступні публікації не видаляють облікові записи й статті: вони зберігаються окремо від дизайну. Публікувати сайт після кожної статті не потрібно.
- Production після цієї реалізації ще не публікувався; повний сценарій підтверджено в робочій версії.

## Перевірка безпеки
- У приватному вікні /admin/insights переводить на сторінку входу.
- Editor при відкритті /admin/users або /admin/editor повертається в Insights.
- Перевірено серверну заборону зміни інших сторінок, створення стороннього контенту і надання собі admin.
- Перевірено: після відкликання доступу вже виданий токен більше не дає прав редагування.
- Перевірено весь шлях тестового Editor: вхід → завантаження обкладинки → чернетка → Preview → Publish → публічна стаття → Unpublish → Delete → Sign out.
- 13 автоматичних перевірок правил доступу, публікації та безпечного тексту пройшли.
